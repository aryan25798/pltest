1. Directory Structure: Where the Notification Code Lives

In our Page Object Model architecture, the Notification Module is split into two cleanly separated layers:

📁 src/main/java/com/example/pages/NotificationsPage.java

Page Object: Contains the locators and actions for the Notifications page (/notifications). Manages polling wait handlers, reading alert card lists, parsing timestamps, checking score thresholds (< 70% vs >= 70%), marking unread alerts as read, clicking refresh, and verifying Pod Isolation.

📁 src/test/java/com/example/tests/NotificationTest.java

Test Script: Contains the automated TestNG test cases (TC_NOTIF_01 through TC_NOTIF_07) plus the Data-Driven Test. It logs in as the Pod Lead before every test, calls NotificationsPage methods, and performs assertions.

📁 src/test/resources/testdata/TestData.xlsx (Sheet: NotificationWorkflow)

Test Data: Holds all test accounts, expected URL fractions, expected alert keywords, threshold percentages, and assigned Pod values.

2. Notification Module: Business Flow & User Story

🎯 Why the Notification Module Exists in ProjectLens

"In ProjectLens, when a Pod Lead submits a project idea, the AI engine evaluates it asynchronously. Later, a Trainer reviews and makes a final decision. The Notification Module is the real-time communication channel that keeps the student Pod informed of every milestone without requiring them to repeatedly poll the submissions page."

The 4 Key Notification Events:

  1. Low Score Warning (< 70%): If the AI alignment score is under 70%, the system sends an urgent alert: "Your project idea '[Title]' needs improvement. Alignment score: [X]%. Please revise and reupload."
  2. High Score Qualified (>= 70%): If the score meets or exceeds 70%, the system sends a success notification: "Your project idea '[Title]' qualified for trainer review with an alignment score of [X]%."
  3. Trainer Decision Alert: When the Trainer reviews the idea, a notification immediately updates the Pod: "Trainer decision for '[Title]': Approved" (or Needs Revision / Rejected).
  4. Chronological Updates & Timestamps: Every notification has a visible date/time stamp and unread status indicator.
  5. Pod Isolation (Multi-Tenancy Security): A Pod Lead of Pod Alpha must only see notifications for Pod Alpha, and never see ideas or alerts from Pod Beta, Gamma, or other teams!

4. NotificationsPage.java — Code & Line-by-Line Explanation

src/main/java/com/example/pages/NotificationsPage.java

What this file is doing: Encapsulates all HTML element locators and action methods for the Notifications screen.

Java Code Line What This Line is Doing in Plain English
package com.example.pages; Defines the package location according to standard Page Object Model convention.
public class NotificationsPage extends BasePage { Inherits browser instance and common helper methods (click, getText, isDisplayed) from BasePage.
private final By notificationsNavTab = By.xpath("//a[contains(@href,'notifications') or contains(.,'Notifications')]"); Locator for the Notifications tab in the left sidebar navigation menu.
private final By notificationsHeader = By.xpath("//h1[contains(.,'Notifications')] | //h2[contains(.,'Notifications')]"); Locator for the page heading to verify navigation success.
private final By refreshButton = By.xpath("//button[contains(.,'Refresh')]"); Locator for the Refresh button at the top of the notifications list.
private final By notificationCards = By.cssSelector("article.card.notification, article.notification"); Locator for individual notification alert cards rendered in the container.
private final By unreadNotificationCards = By.cssSelector("article.card.notification.unread, article.unread"); Locator for unread notification cards that have a bold or unread border class.
private final By notificationMessages = By.cssSelector(".notification-message, .notification-content"); Locator targeting the inner message text container of each alert card.
private final By notificationDates = By.cssSelector(".notification-date, span[class*='date'], time"); Locator for the date/time timestamp rendered on each alert card.
private final By markAsReadButton = By.xpath(".//button[contains(.,'Mark as read')] | .//span[contains(.,'Mark as read')]"); Relative XPath to locate the "Mark as read" button inside any specific notification card.
public NotificationsPage(WebDriver driver) { super(driver); } Constructor: Receives the WebDriver instance and passes it to BasePage.
public void navigateToNotifications() { WebElement nav = WaitUtils.waitForElementVisible(driver, notificationsNavTab, 10); try { nav.click(); } catch (Exception e) { ((JavascriptExecutor) driver).executeScript("arguments[0].click();", nav); } WaitUtils.waitForUrlContains(driver, "notifications", 10); waitForNotificationsToLoad(); } Navigates to the notifications page: 1. Waits up to 10 seconds for the left sidebar link to become visible. 2. Clicks it (with JavaScript fallback). 3. Waits for the URL to change to /notifications. 4. Waits for the async cards to load from the server.
public void waitForNotificationsToLoad() { try { for (int i = 0; i < 20; i++) { List<WebElement> cards = driver.findElements(notificationCards); if (!cards.isEmpty()) { break; } Thread.sleep(500); } } catch (InterruptedException ignored) {} } Asynchronous Polling Handler: Polls every 500ms up to 10 seconds until cards are rendered in the DOM. Prevents false-negative zero-count assertions!
public int getNotificationCount() { return getAllNotificationCards().size(); } Returns the total number of notification alert cards currently displayed on screen.
public boolean areTimestampsDisplayed() { List<WebElement> dates = driver.findElements(notificationDates); if (dates.isEmpty()) return false; for (WebElement d : dates) { if (!d.getText().trim().isEmpty()) { return true; } } return false; } Inspects all date elements on the page and verifies that at least one valid timestamp string is visible.
public boolean hasLowScoreAlert() { for (String msg : getAllNotificationMessages()) { if (msg.contains("needs improvement") && msg.contains("Alignment score:")) { return true; } } return false; } Scans all notification message bodies to verify if an AI low-score alert (< 70%) was delivered.
public boolean hasHighScoreAlert() { for (String msg : getAllNotificationMessages()) { if (msg.contains("qualified for trainer review")) { return true; } } return false; } Scans messages to verify if an AI high-score qualification alert (>= 70%) was delivered.
public boolean hasTrainerDecisionAlert() { for (String msg : getAllNotificationMessages()) { if (msg.toLowerCase().contains("trainer decision for")) { return true; } } return false; } Scans messages to verify if a Trainer evaluation decision (Approved, Rejected, Revision) was logged.
public boolean markFirstUnreadNotificationAsRead() { List<WebElement> unreadCards = driver.findElements(unreadNotificationCards); if (!unreadCards.isEmpty()) { WebElement btn = unreadCards.get(0).findElement(markAsReadButton); btn.click(); return true; } return false; } Finds the first unread card, clicks its "Mark as read" button, and triggers the status update to "Read".
public void clickRefresh() { WebElement btn = WaitUtils.waitForElementVisible(driver, refreshButton, 10); btn.click(); waitForNotificationsToLoad(); } Clicks the Refresh button and synchronizes until updated cards reload from the server.
public boolean verifyPodIsolation(String assignedPod) { List<WebElement> cards = getAllNotificationCards(); String[] otherPods = { "Pod Beta", "Pod Gamma", "Pod Delta", "Pod Omega" }; for (WebElement card : cards) { String text = card.getText(); for (String other : otherPods) { if (text.contains(other)) { return false; } } } return true; } Security & Isolation Verifier: Iterates through all cards visible to the current Pod Lead. If any card contains the name of another Pod, returns false, failing the security test!

7. How the Supporting Framework Connects to Notifications

  • BasePage & WaitUtils: NotificationsPage extends BasePage to use explicit WebDriverWait. Because notifications are generated asynchronously, the custom method waitForNotificationsToLoad() polls every 500ms to guarantee cards are present before assertions execute.
  • BaseTest: Handles browser setup before each test and browser closure after each test.
  • DataProviders.java: Connects to TestData.xlsx using method: 
    public static Map<String, String> getNotificationTestCaseData(String tcId) {
    ExcelReader excel = new ExcelReader(EXCEL_PATH);
    return excel.getTestCaseData("NotificationWorkflow", tcId);
}

8. How ExtentReports Logs Notification Tests

Inside TestListener.java:

  1. When NotificationTest runs, the listener assigns the category: test.assignCategory("Notification Module");
  2. The 14 tests appear under the Notification Module tab on the left of test-output/ExecutionReport.html.
  3. If an alert fails to match or a timestamp is missing, TakesScreenshot captures a screenshot and embeds it into the report.

10. Top 15 Notification Module Interview Q&A

Q1: How do you handle asynchronous loading of notification cards?

"In NotificationsPage.java, I implemented waitForNotificationsToLoad(), which polls the DOM every 500ms up to 10 seconds until cards are rendered. This prevents false failures caused by network latency."

Q2: How do you verify that timestamps are displayed on notifications?

"I use driver.findElements(notificationDates) to retrieve all timestamp elements, iterate through them, and assert that the text is non-empty."

Q3: How do you test the 70% threshold logic in notifications?

"We test two opposite scenarios: TC_NOTIF_02 asserts that scores under 70% produce a 'needs improvement' warning with re-upload instructions; TC_NOTIF_03 asserts that scores of 70% or higher produce a 'qualified for trainer review' notification."

Q4: How do you automate the 'Mark as read' functionality?

"The test locates unread notification cards, clicks the 'Mark as read' button, waits for the DOM mutation, and asserts that the card's text or CSS indicator updates to 'Read'."

Q5: What is Pod Isolation and how did you automate it?

"Pod Isolation is a multi-tenancy security rule: a Pod Lead should only see notifications for their assigned Pod. In verifyPodIsolation(), we scan all rendered notification cards to ensure none contain the names of other pods (e.g. Pod Beta, Pod Gamma)."

Q6: Why did you use findElements() instead of findElement() for cards?

"findElements() returns a list of all matching cards. If there are 0 cards initially, it returns an empty list without throwing NoSuchElementException, allowing our wait loop to poll cleanly."

Q7: What happens when the user clicks the Refresh button?

"TC_NOTIF_06 clicks the Refresh button, waits for the cards to reload, and asserts that the notification count is preserved or updated from the backend."

Q8: How is test data passed to NotificationTest?

"We use Apache POI in DataProviders.getNotificationTestCaseData() to read from the NotificationWorkflow sheet in TestData.xlsx."

Q9: What is the benefit of Data-Driven Testing (DDT) in notifications?

"We can test different user roles, alert keywords, and pod assignments simply by updating Excel without modifying Java test code."

Q10: How do you capture screenshots on notification failures?

"If an expected alert text is not found, TestNG triggers TestListener.onTestFailure(), which captures a Base64 screenshot and attaches it directly into ExecutionReport.html."

Q11: How do you handle element clicks intercepted by animations on notifications?

"We use a fallback to JavascriptExecutor:
((JavascriptExecutor) driver).executeScript("arguments[0].click();", element);"

Q12: How do you run only the Notification module from the terminal?

"Command: mvn test -Dtest=NotificationTest"

Q13: How do you run a single notification test case?

"Command: mvn test -Dtest=NotificationTest#testTC_NOTIF_02_LowScoreAlert"

Q14: How does BaseTest support NotificationTest?

"BaseTest handles opening the browser in @BeforeMethod and quitting it in @AfterMethod, ensuring a fresh session for each test."

Q15: How many notification tests are there and do they all pass?

"There are 14 tests in total (7 data-driven row iterations + 7 specific functional tests), and all 14 pass with 100% success rate."
