2. Notification Module: Business Flow & User Story

ðŸŽ¯ Why the Notification Module Exists in ProjectLens

"In ProjectLens, when a Pod Lead submits a project idea, the AI engine evaluates it asynchronously. Later, a Trainer reviews and makes a final decision. The Notification Module is the real-time communication channel that keeps the student Pod informed of every milestone without requiring them to repeatedly poll the submissions page."

The 4 Key Notification Events:

  1. Low Score Warning (< 70%): If the AI alignment score is under 70%, the system sends an urgent alert: "Your project idea '[Title]' needs improvement. Alignment score: [X]%. Please revise and reupload."
  2. High Score Qualified (>= 70%): If the score meets or exceeds 70%, the system sends a success notification: "Your project idea '[Title]' qualified for trainer review with an alignment score of [X]%."
  3. Trainer Decision Alert: When the Trainer reviews the idea, a notification immediately updates the Pod: "Trainer decision for '[Title]': Approved" (or Needs Revision / Rejected).
  4. Chronological Updates & Timestamps: Every notification has a visible date/time stamp and unread status indicator.
  5. Pod Isolation (Multi-Tenancy Security): A Pod Lead of Pod Alpha must only see notifications for Pod Alpha, and never see ideas or alerts from Pod Beta, Gamma, or other teams!

7. How the Supporting Framework Connects to Notifications

  • BasePage & WaitUtils: NotificationsPage extends BasePage to use explicit WebDriverWait. Because notifications are generated asynchronously, the custom method waitForNotificationsToLoad() polls every 500ms to guarantee cards are present before assertions execute.
  • BaseTest: Handles browser setup before each test and browser closure after each test.
  • DataProviders.java: Connects to TestData.xlsx using method: 
    public static Map<String, String> getNotificationTestCaseData(String tcId) {
    ExcelReader excel = new ExcelReader(EXCEL_PATH);
    return excel.getTestCaseData("NotificationWorkflow", tcId);
}

10. Top 15 Notification Module Interview Q&A

Q1: How do you handle asynchronous loading of notification cards?

"In NotificationsPage.java, I implemented waitForNotificationsToLoad(), which polls the DOM every 500ms up to 10 seconds until cards are rendered. This prevents false failures caused by network latency."

Q2: How do you verify that timestamps are displayed on notifications?

"I use driver.findElements(notificationDates) to retrieve all timestamp elements, iterate through them, and assert that the text is non-empty."

Q3: How do you test the 70% threshold logic in notifications?

"We test two opposite scenarios: TC_NOTIF_02 asserts that scores under 70% produce a 'needs improvement' warning with re-upload instructions; TC_NOTIF_03 asserts that scores of 70% or higher produce a 'qualified for trainer review' notification."

Q4: How do you automate the 'Mark as read' functionality?

"The test locates unread notification cards, clicks the 'Mark as read' button, waits for the DOM mutation, and asserts that the card's text or CSS indicator updates to 'Read'."

Q5: What is Pod Isolation and how did you automate it?

"Pod Isolation is a multi-tenancy security rule: a Pod Lead should only see notifications for their assigned Pod. In verifyPodIsolation(), we scan all rendered notification cards to ensure none contain the names of other pods (e.g. Pod Beta, Pod Gamma)."

Q6: Why did you use findElements() instead of findElement() for cards?

"findElements() returns a list of all matching cards. If there are 0 cards initially, it returns an empty list without throwing NoSuchElementException, allowing our wait loop to poll cleanly."

Q7: What happens when the user clicks the Refresh button?

"TC_NOTIF_06 clicks the Refresh button, waits for the cards to reload, and asserts that the notification count is preserved or updated from the backend."

Q8: How is test data passed to NotificationTest?

"We use Apache POI in DataProviders.getNotificationTestCaseData() to read from the NotificationWorkflow sheet in TestData.xlsx."

Q9: What is the benefit of Data-Driven Testing (DDT) in notifications?

"We can test different user roles, alert keywords, and pod assignments simply by updating Excel without modifying Java test code."

Q10: How do you capture screenshots on notification failures?

"If an expected alert text is not found, TestNG triggers TestListener.onTestFailure(), which captures a Base64 screenshot and attaches it directly into ExecutionReport.html."

Q11: How do you handle element clicks intercepted by animations on notifications?

"We use a fallback to JavascriptExecutor:
((JavascriptExecutor) driver).executeScript("arguments[0].click();", element);"

Q12: How do you run only the Notification module from the terminal?

"Command: mvn test -Dtest=NotificationTest"

Q13: How do you run a single notification test case?

"Command: mvn test -Dtest=NotificationTest#testTC_NOTIF_02_LowScoreAlert"

Q14: How does BaseTest support NotificationTest?

"BaseTest handles opening the browser in @BeforeMethod and quitting it in @AfterMethod, ensuring a fresh session for each test."

Q15: How many notification tests are there and do they all pass?

"There are 14 tests in total (7 data-driven row iterations + 7 specific functional tests), and all 14 pass with 100% success rate."
