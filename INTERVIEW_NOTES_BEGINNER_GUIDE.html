2. How the Page Object Model (POM) Works Together

Here is how control flows when a test runs:

ðŸ”„ The 3-Step Execution Cycle
  1. BaseTest (@BeforeMethod): Launches Chrome browser, maximizes the window, and opens the login URL.
  2. Test Method (e.g. TrainerReviewTest):
    • Calls LoginPage.login() to authenticate as Trainer.
    • Calls ReviewsPage.navigateToReviews() to open the review queue.
    • Calls ReviewsPage.clickApprove() to approve the idea.
    • Runs Assert.assertTrue(...) to verify the decision updated the queue.
  3. BaseTest (@AfterMethod): Closes the Chrome browser cleanly.

public class ReviewsPage extends BasePage { Declares ReviewsPage and inherits common helper methods (click, enterText, getText) from BasePage.

private final By decisionQueueHeader = By.xpath("//h2[contains(text(),'Decision queue')]"); Locator for the header title "Decision queue". Used to verify that the Trainer has successfully reached the reviews page.
private final By reviewItems = By.cssSelector("button.review-item"); Locator for each pending submission card button inside the queue list.
private final By detailPanel = By.cssSelector(".detail-panel, section[class*='detail']"); Locator for the right-hand panel that opens when a Trainer clicks a submission to read its details.
private final By projectTitle = By.cssSelector(".detail-head h3, .detail-panel h3, h3"); Locator for the project's title inside the detail panel.
private final By commentsTextarea = By.cssSelector("textarea[placeholder*='Add comments for the pod']"); Locator for the feedback text box where the Trainer types remarks for the pod.

private final By reviseButton = By.cssSelector("button.decision.revise, button[class*='revise']"); Locator for the "Needs Revision" button.

public ReviewsPage(WebDriver driver) { super(driver); } Constructor: Receives the browser driver from the test and passes it to BasePage using super(driver).
public void navigateToReviews() { WebElement nav = WaitUtils.waitForElementVisible(driver, reviewsNavTab, 10); try { nav.click(); } catch (Exception e) { ((JavascriptExecutor) driver).executeScript("arguments[0].click();", nav); } WaitUtils.waitForUrlContains(driver, "reviews", 10); } Waits up to 10 seconds for the "Reviews" tab to be visible, clicks it (with a JavaScript click fallback if blocked), and waits until URL contains "reviews".
public boolean isDecisionQueueDisplayed() { return isDisplayed(decisionQueueHeader); } Checks if the "Decision queue" title is visible on screen. Returns true or false.
public int getQueueItemCount() { List<WebElement> items = driver.findElements(reviewItems); return items.size(); } Counts how many pending submissions are currently in the queue.
public void selectFirstSubmission() { List<WebElement> items = driver.findElements(reviewItems); if (!items.isEmpty()) { items.get(0).click(); } } Clicks the first pending project in the list to open its details panel.
public boolean isSubmissionDetailsDisplayed() { return isDisplayed(detailPanel) || isDisplayed(projectTitle); } Verifies if the right-side detail panel has opened.
public void enterComments(String comments) { enterText(commentsTextarea, comments); } Types the trainer's feedback comments into the textarea.
public void clickApprove() { WebElement btn = WaitUtils.waitForElementVisible(driver, approveButton, 10); try { btn.click(); } catch (Exception e) { ((JavascriptExecutor) driver).executeScript("arguments[0].click();", btn); } } Waits up to 10 seconds for the Approve button, clicks it, and sends the approval decision to the system.
public void clickNeedsRevision() { WebElement btn = WaitUtils.waitForElementVisible(driver, reviseButton, 10); try { btn.click(); } catch (Exception e) { ((JavascriptExecutor) driver).executeScript("arguments[0].click();", btn); } } Clicks the "Needs Revision" button to return the idea to the pod for changes.
public void clickReject() { WebElement btn = WaitUtils.waitForElementVisible(driver, rejectButton, 10); try { btn.click(); } catch (Exception e) { ((JavascriptExecutor) driver).executeScript("arguments[0].click();", btn); } } Clicks the "Reject" button to finalize rejection of the submission.

17. Top 15 Selenium Interview Questions & Answers

Q1: Why did you use Page Object Model (POM)?

"POM separates page locators and actions into Page classes, away from test assertions. If UI changes occur, we only update the locator in one place without breaking multiple tests."

Q2: What is the difference between findElement() and findElements()?

"findElement() returns a single element and throws NoSuchElementException if missing. findElements() returns a list and simply returns an empty list if no elements match."

Q3: How do you handle waits in your framework?

"We use Explicit Waits (WebDriverWait) in WaitUtils.java with conditions like visibilityOfElementLocated and elementToBeClickable instead of hardcoded sleeps."

Q4: Why did you use ThreadLocal in DriverManager?

"ThreadLocal gives each running test thread its own separate WebDriver instance, preventing collisions when running tests in parallel."

Q5: How does your framework capture screenshots on failure?

"In TestListener.java's onTestFailure() callback, we cast driver to TakesScreenshot, capture the screenshot as Base64, and embed it into ExtentReports."

Q6: What is the difference between @BeforeMethod and @BeforeClass?

"@BeforeMethod runs before every single test method (used to open a fresh browser in BaseTest). @BeforeClass runs only once before the whole class starts."

Q7: What does -D mean in Maven commands like mvn test -Dtest=TrainerReviewTest?

"-D defines a Java System Property. It tells Maven's Surefire plugin to run only that specific test class instead of the entire suite."

Q8: How did you implement Data-Driven Testing (DDT)?

"We use Apache POI in ExcelReader.java to read rows from TestData.xlsx. TestNG's @DataProvider in DataProviders.java feeds that data into our tests."

Q9: How do you handle elements that cannot be clicked normally?

"We use JavascriptExecutor:
((JavascriptExecutor) driver).executeScript("arguments[0].click();", element);
This directly triggers the DOM click event."

Q10: What is Hard Assert vs Soft Assert?

"Hard Assert stops test execution immediately if the condition fails. Soft Assert records the failure and continues executing the remaining steps."

Q11: What challenges did you face in Trainer Review module?

"Asynchronous queue loading: elements took time to render after page load. I solved it by wrapping interactions with explicit waits in WaitUtils."

Q12: How do you run tests in headless mode?
